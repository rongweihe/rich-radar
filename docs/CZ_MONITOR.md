# CZ 言论雷达：实现与稳定性边界

## 当前架构

```text
GitHub Actions（单写者，每 15 分钟尝试）
  ├─ twscrape：自己的 X 登录会话 → 数字用户 ID + 用户名校验
  └─ 可选 RSS：主源失败时读取 → 明确标注二手来源
       ↓ 规范化、去重、修订保护、窗口重叠检查
  中文/英文规则 → data/cz.json + 来源健康状态
       ↓ 白名单构建 → Pages 显式部署 → 线上哈希核对
  浏览器每 60 秒读快照 → 原文 / 命中依据 / 时间 / 页内提醒
```

原项目的市场评分仍由 `compute.py` 每周计算，EMA 由 `compute_ema.py` 每日计算、浏览器补更新加密 EMA；研究卡仍由人工维护。CZ 作为独立模块，不修改恐慌分数或观察价。`refresh.py` 将三种更新合并为一个写入队列，用完成周期补跑错过的每日/每周任务。

## 为什么这样选型

调研与接口核验日期：2026-10-25。优先接现有库，不自写 X GraphQL 客户端，不复制其他项目源代码。

| 候选 | 依赖与已知问题 | 决策 |
|---|---|---|
| [twscrape](https://github.com/vladkens/twscrape)，MIT | Python、HTTPX、账号池和 SQLite；有近期维护与发布。依赖 Cookie、X 内部接口，会话失效、限流、空响应和上游改版仍可能发生 | 采用固定 0.20.1，核对已安装 API/数据模型；外加限时、降级和覆盖检查 |
| [RSSHub](https://github.com/DIYgod/RSSHub)，AGPL-3.0 | Node 服务，X 路由通常仍需认证和部署资源；不能保证公共实例可用 | 不打包、不复制实现；仅允许用户接入已验证 RSS，通过 BSD 解析库读取 |
| [Nitter](https://github.com/zedeus/nitter)，AGPL-3.0 | 上游归档/维护风险，公开实例与 X 会话条件不稳定 | 不作为默认源，不维护随机实例池 |
| [Twikit](https://github.com/d60/twikit)，MIT | 同样依赖 X 非官方接口和登录态，切换库无法消除核心不稳定因素 | 不同时叠加第二套账号采集栈 |
| [changedetection.io](https://github.com/dgtlmoon/changedetection.io)，Apache-2.0 | 通用网页变更监测，需要常驻服务，页面噪声与登录页会干扰检测 | 借鉴状态、历史和故障可见性思路；本项目不引入服务 |

只对接库公开 API；依赖与许可证链接见 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)。主依赖与当前验证过的间接依赖分别固定在 `requirements-cz.txt` / `requirements-cz.lock`，升级时运行测试并重新验证授权账户的真实采集。

## 分析规则

- 明确买入倾向：买入表达 + BTC/Bitcoin/比特币，或逆向/机会语境。
- 逆向机会：机会表达 + 下跌、恐慌等逆向语境或资产名。
- 疑似长期暗示：长期/耐心/未来自我等叙述，加纯文字少 emoji 或资产相关语境。不能仅凭 `year` / “未来”命中。
- 否定买入、推广抽奖、回复和转推排除；引用帖、正文完整性未知降为「待核对」。
- “纯文字、emoji 少”只是辅助特征。“严肃”与潜台词无法可靠用确定性规则证明，所以不用伪精确置信度，不宣称拉盘预测。

示例文案只用于离线测试，不写入公开数据。没有实时原文时页面为空并说明原因。规则仍可能误判反讽、转述、复杂否定或非投资的长期叙述；「最近原文」用于人工复核。改规则版本不改首次发现时间，也不把历史重新推送。

## 对抗性检查后的防护

1. **静默漏报**：空时间线视为异常；有数据也需与上次最新 ID 重叠，才标记检查正常。RSS 无法证明连续性，始终降级。上游库可能静默结束分页，窗口重叠也不能证明中间没有漏帖。
2. **旧数据装实时**：分别记录原文发布时间、首次发现、快照生成、最后成功读取；浏览器按检查时间判断过期。长时间没发文不等于采集失效。
3. **历史轰炸**：初次采集及超 60 分钟补采标记历史；首次页面加载静默。已编辑、降级源和旧文不弹新提示；提示仅限打开页面期间。
4. **重复/乱序编辑**：推文 ID 始终用字符串；编辑链折叠为一个记录，保留首次发现，旧修订不能覆盖较新的文本。无法取得编辑链时仍可能出现分开的版本。
5. **局部故障**：主源超时保留已收到的部分原文但不推进成功状态；硬失败恢复上次快照，退避状态跨 Actions 运行保存。来源恢复后也需重新检查覆盖。
6. **内容与会话隔离**：外部正文用 `textContent` 渲染；RSS HTML 转纯文本；原帖链接由校验后的数字 ID 构造。会话只写临时库，异常不原样放进公开 JSON。
7. **发布失真**：单写者 + 完成周期解决并发覆盖；Git 推送冲突直接失败，不合并未经测试的新代码。显式 Pages 发布绕开机器人提交不触发构建的问题；部署后验证线上内容。

## 尚不能保证的部分

免费 X 非官方采集没有 SLA，Cookie/账号/上游接口可能失效；GitHub 定时任务可能延迟或停止。页面只能展示最后可取得的数据。严重断流超过读取窗口会留下可见的覆盖缺口；不自动重置锚点掩盖缺口。

不提供页面关闭后的系统推送、短信或 Telegram；当前“推送”是页面自动更新与页内新命中提示。若以后需要持续强提醒，应另接通知通道和独立故障告警；若需要更强时效保证，再评估授权付费数据源或常驻服务。

本地测试不替代真实账号验收。部署后按 [DEPLOYMENT.md](../DEPLOYMENT.md) 连续运行两次、核对原文与健康状态，再观察连续运行表现。
